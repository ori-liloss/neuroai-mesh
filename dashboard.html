Over time

Each point is one time slice. The last slice is still filling: its rate is divided by the seconds it really covers, not by the full slice.

Writing speed by computer

all, last hour–

How many tokens each computer's model wrote per second, as answers it finished. Counted as: the output tokens its model reported for every answer that finished in the slice, divided by the slice's seconds. This is the true speed of a computer: unlike "jobs per hour" it does not drop just because the answers got longer. A line falling to zero means that computer wrote nothing in that slice.

Finished jobs per hour

answers writtenchecks run

Two kinds of job, kept apart because they are not comparable: writing one answer takes minutes, one check takes seconds. Answers = successful generate attempts; checks = every finished check (Luau, Python, math, tests…). Rate = count in the slice × 3600 ÷ seconds in the slice.

Average answer length

last hour–

Tokens in an average finished answer: all output tokens of the slice ÷ the answers that finished in it. When this rises, each answer takes longer, so fewer answers finish per hour even though the computers are just as fast. That is why the number of jobs alone can look like a slowdown.

Failed and cut-off answers

failed attemptscut off at the length limit

Failed attempts = generate attempts that did not return an answer ÷ all generate attempts in the slice; this includes time-outs that went back to the queue (nothing lost, but time was). Cut off = answers the model stopped because they reached the token limit ÷ answers in the slice; a cut-off answer is retried once with more room and never trained on.

Open jobs

answers to writechecks waiting

Jobs queued or running at the end of each slice. The last point is the exact number open now; earlier points are walked back from it through the log: every job added after that moment was not there yet, every job finished after it was still open. A falling line is the queue being worked off; a jump up is new jobs added.

Computers in the last hour

counted from their finished attempts

Tokens/s = output tokens of its finished answers in the last hour ÷ the seconds of that hour that count (a stretch of over 15 minutes in which no computer reported anything, like the main PC being off, is left out, because nothing could be recorded then). Avg length = those tokens ÷ its answers. Failed = attempts that ended with no answer for good. Retries = attempts where the model timed out or the connection to it dropped: those jobs went back to the queue, so nothing was lost. Last = time since it finished anything. A computer that finished nothing in this window is not listed.

Loading…

Each column is one layer of the model, left to right in the order a word passes through them. Its 32 dots are 32 slices of the model's 4,096-number "residual stream" (128 numbers each): a dot's brightness is how much this training changed what the layer writes into that slice (dim = the smallest changes, bright = the largest; the two ends are printed above the picture). The lines are the residual stream itself, carrying each slice from one layer to the next; a line glows when the layers on both ends changed in that slice. Computed exactly from the adapter files (each change is two small matrices B·A, measured as the Frobenius norm ‖ΔW‖), so nothing here is a guess. Click a column to open that layer.

Layer –

Click a column above.

change in this layer–

Left, attention: the stream's 32 slices feed the attention projections (q, k, v; on DeltaNet layers qkv and its gates z, a, b); the attention output goes back into the stream. Right, the MLP: 4,096 stream numbers → 12,288 neurons (32 groups of 384) → back to the stream. Every line is a real block of the change matrix ΔW between two groups: its brightness is that block's ‖ΔW‖, so the bright web is exactly where this stage rewired the layer. Each of the four maps is scaled to its own largest block (the output matrices change much less than the input ones), so compare lines within a map, and use the numbers on hover across maps.

How the model is learning

Hover or tap any graph to read exact values. Steps run along the bottom; only the current run is drawn.

Loss

raw smoothed eval
latest–

no loss yet

Loss is how wrong the model still is: lower is better. The amber line is measured on the batches it just trained on, the teal dots on held-out data it never trains on. If teal starts rising while amber keeps falling, the model is memorising instead of learning.

Eval loss by area

one line per kind of data · lower is better

overall–

Each line is the model's loss on one kind of held-out data (decompiled code, Ghidra output, C++, Python, Luau…). A line that falls is a skill getting better; a flat or rising line is a weak spot the run is not fixing.

Learning rate

now–

How big each update to the weights is. It normally warms up, then slowly decays toward zero; near the end small steps let the model settle into what it learned.

Gradient norm

latest–

How hard the latest batch pushed on the weights. Short spikes are surprising batches and are normal; a steady climb or huge spikes can mean training is becoming unstable.

Speed

steps / hour–

Seconds per training step (lower is faster). A sudden jump usually means the GPU is shared with another program, or its memory is full and spilling into slower system memory.

Progress & ETA

finish in–

Steps completed against time since this session of the run started. The dashed line projects the rest at the current speed: where it meets the goal line is the estimated finish.

GPU on the training PC

Sampled every 15 seconds, kept for 24 hours.

Utilization

now–

How busy the GPU is. Close to 100% while training means it is doing real work; regular dips mean it is waiting for data or for the CPU.

Power

now–

Power draw in watts. It follows the work: a steady line near the dashed limit means the card runs flat out.

Temperature

now–

GPU core temperature. Under about 80 °C is comfortable; far above that the card slows itself down to stay safe.

Video memory

in use–

Video memory in use against the card's total (dashed). When it is full, data spills into much slower shared system memory (red line), and steps get slower.
